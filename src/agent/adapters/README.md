# adapters

Outbound adapters — the clients that talk to external systems. Each implements a `core/protocols/` interface and translates third-party exceptions into `AgentError` subclasses at the boundary.

## Contents

- `litellm.py` — `LiteLLMAdapter`, implements `ILLM` via `litellm`, giving access to any provider litellm supports through one adapter. Constructed with per-model `temperature`/`top_p`/`max_tokens` defaults; each `complete()` call can override any of them and optionally offer `tools` (OpenAI-format function schemas) — any `tool_calls` the LLM returns are mapped onto the result, never executed. `LiteLLMAdapter.from_config(llm_config: LLMConfig)` is the classmethod `core/factories/app.py` builds from -- the one place `LLMConfig`'s fields are unpacked into `__init__`'s matching parameters, so a config caller never has to repeat that field-by-field mapping itself; `__init__` itself stays plain keyword parameters (not `LLMConfig`-shaped) since tests construct it directly with hand-picked values that aren't always a full config. `max_input_tokens()` returns the model's real context-window size via `litellm.get_model_info()`, a local lookup with no network call -- unless constructed with `context_window`, in which case that value is returned directly, unconditionally, with no litellm lookup at all; `complete()` maps `litellm.ContextWindowExceededError` to `LLMContextWindowExceededError`, checked before the generic status-code mapping. The retry loop (`num_retries`, exponential backoff) only ever wraps the network call itself (`litellm.acompletion()`) -- parsing/constructing the result from a *successful* response happens outside that try/except, so a malformed response shape (empty `choices`, a missing field) is classified as `LLMError` and raised immediately, once, never silently retried `num_retries` times first (it has no `.status_code`, so the retry classifier would otherwise treat it as a transient failure). Whenever a `complete()` call has no `tools` (`None` or `[]`), it first folds that call's `messages` through `flatten_tool_exchanges_for_no_tools_request` (`core/models/message.py`), turning each turn's tool calls and results into plain assistant text before anything goes on the wire — some providers, Bedrock's Converse API confirmed, reject a request carrying `role="tool"` messages or `tool_calls` when it declares no `tools`, even where those merely replay an earlier exchange. This is the `ILLM` contract's requirement, satisfied here once for every caller: it is unconditional, independent of why this particular caller has no tools (a summarizer call, `ReactStrategy`'s forced final call, or its main loop on a run resolved to no tools at all), and a no-op for a message list holding no tool-shaped content. Callers therefore always pass real, un-pre-processed history and never flatten anything themselves; a request that *does* declare tools is untouched and replays the genuine tool blocks.
