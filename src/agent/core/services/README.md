# services

Use-case orchestration, called by inbound adapters. Each file's own docstrings carry the
full rationale for its design decisions -- this file is a short index, not a duplicate.

## Contents

- `agent_run.py` — `AgentRunService.run()`, the single entry point for one agent turn: resolves the agent/model/strategy/tools, enforces `max_input_chars` / allow-list ceilings / `max_request_seconds`, threads and (if configured) proactively compacts session history, delegates to the selected `IStrategy`, and reactively retries once through compaction on a context-window overflow. Binds `core.run_context.run_context()` around the whole call (see `core/run_context/README.md`) and rejects a concurrent second call on the same session via `ISessionStore.busy()`. After a successful run, it's the sole writer to both `CostTracker.record()` (that run's token/cost usage) and `ContextFootprintTracker.record()` (the session's new context size) -- two separate calls, since cumulative usage (a counter) and context footprint (a gauge) are different kinds of value with different update rules.
- `compaction.py` — `CompactionService`, keeps a session's stored history under its configured token budget: `maybe_compact` (the proactive path, reading `ContextFootprintTracker`) and `compact` (called directly by `agent_run.py` on a reactive overflow, and which calls `ContextFootprintTracker.forget()` on success since the old footprint no longer describes the shrunk history) for the summarization itself. Never corrupts stored history -- an unusable or non-shrinking summary leaves history untouched. Falls back to chunked map-reduce summarization if a single-pass summary itself overflows.
- `context_tracker.py` — `ContextFootprintTracker`, the single source of truth for "how big is this session's stored history right now": `record()`/`get()`/`forget()`, LRU-bounded by `max_sessions`, eviction not busy-aware. Written only by `agent_run.py`; read by both `compaction.py` (to decide whether to trigger compaction) and `session_service.py` (for the usage endpoint's `context_tokens` field) -- neither of those two depends on the other, both depend only on this. Putting the value on either of them instead would create a circular dependency (`CompactionService` already sits downstream of `AgentRunService`) or make `context_tokens` disappear whenever compaction is disabled (`CompactionService` isn't constructed at all in that case).
- `cost_tracker.py` — `CostTracker`, cumulative token/cost tracking per session and per agent: `record()` folds one run's usage into both a per-session (LRU-bounded by `max_sessions`) and a per-agent (unbounded) running total -- a counter, only ever summed, never overwritten. `agent_usage()` reads the per-agent total; `forget()` discards a deleted session's cumulative entry (never the agent's own lifetime total). No config surface -- constructed directly in `api/app.py`'s `create_app()`, same precedent as `InMemorySessionStore`.
- `session_service.py` — `SessionService`, the session-lifecycle use case an inbound adapter shouldn't reimplement itself: `get_history()` is a passthrough, `delete()` orchestrates `ISessionStore.busy()` + `ISessionStore.delete()` + `CostTracker.forget()` + `ContextFootprintTracker.forget()` together so a future `cli/` adapter reuses this instead of rediscovering the same sequence. Has no direct dependency on `CompactionService` -- that service keeps no state of its own left to forget. `get_usage()` composes two independent reads -- `CostTracker.session_usage()` and `ContextFootprintTracker.get()` -- after confirming the session exists, each defaulting to its own zero value independently if missing.
