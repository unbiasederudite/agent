# models

Pydantic data models.

## Contents

- `message.py` — `Message`, the OpenAI-compatible wire format for a single chat message (`role` includes `"tool"`, paired with `tool_call_id` and `name`, for tool-execution results); `ToolCall`/`ToolCallFunction`, one tool invocation an LLM requested, in litellm/OpenAI's nested wire shape (matches litellm's response exactly, so mapping and outbound serialization are both plain, direct operations); `flatten_tool_exchanges_for_no_tools_request`, a pure `Message`-list utility that folds each turn's tool calls and results into that turn's final assistant message, making a list safe to send to any request that declares no `tools` (Bedrock's Converse API rejects toolUse/toolResult blocks when `toolConfig` is absent, even for messages merely replaying a prior exchange) — called in exactly one place, `LiteLLMAdapter.complete()`, which applies it automatically to any call with no `tools`; no `core/` caller invokes it by hand
- `usage.py` — `Usage` (frozen/immutable), token counts and USD cost (`cost_usd`, `None` if the model's pricing is unknown) for one completion; `ZERO_USAGE`, the shared all-zero `Usage` constant both `CostTracker` and `SessionService` default to rather than each defining their own copy; `sum_usage()`, adds two `Usage` totals together field by field, `cost_usd`-`None`-safe -- used both by `react.py`'s multi-call turn aggregation and by `CostTracker`'s cumulative tracking
- `completion.py` — `Completion`, the result of one `ILLM.complete()` wire call
- `turn.py` — `Turn`, the aggregate result of one `IStrategy.run()` call: every message it generated (`messages`), summed `usage`, `final_total_tokens` (the last individual call's total, compaction's own bookkeeping signal), and the terminal `finish_reason` — distinct from `Completion`, which is just one wire call's result
- `run.py` — `Run`, the domain record of one completion execution, including the `session_id` it belongs to
- `config.py` — every model in this file (`SamplingDefaults` and, through it, `LLMConfig`/`AgentConfig`, plus `ToolConfig`, `StrategyConfig`, `CompactionConfig`, `LoggingConfig`, `AppConfig`) sets `model_config = ConfigDict(extra="forbid")`: an unrecognized field in the startup JSON (a typo'd key, a stale option) raises `ValidationError` at load time instead of silently being ignored. `SamplingDefaults` (shared temperature/top_p/max_tokens fields; enforces the same universal, provider-independent lower bounds `api/schemas.py`'s `AgentRunRequest` does -- `temperature >= 0`, `top_p` in `[0, 1]`, `max_tokens >= 1` -- so a bad startup-config value is rejected the same way a bad per-request override already is; no upper bound on `temperature`, left to the provider since it's provider-specific), `LLMConfig` (includes optional `context_window`, overriding litellm's own context-window lookup for `CompactionService`'s budget check, plus retry/timeout/concurrency settings: `num_retries`, `timeout`, `retry_base_delay`, `retry_max_delay`, `retry_multiplier`, `max_concurrent_requests`), `AgentConfig` (includes `strategy`, `max_tool_iterations`, `max_input_chars`, `max_tool_result_chars`, capping a single tool call's result length within one run, `max_tool_calls_per_round`, capping how many of one LLM response's tool calls execute, `max_tool_results_total_chars`, capping the combined tool-result content across a whole run, `allowed_tools`/`allowed_models`/`allowed_strategies`, per-agent ceilings on what a request may ever specify — `None` means unrestricted, `[]` (only meaningful for `allowed_tools`) forbids the whole category, a non-empty list restricts to exactly those names, and each agent's own configured defaults must already fall within its own ceiling, enforced by a `model_validator`, and `max_request_seconds`, an overall wall-clock budget for one `AgentRunService.run()` call — retries, tool rounds, and any reactive compaction-and-retry combined — enforced by a single `asyncio.wait_for()` wrapper, `None` meaning unbounded), `ToolConfig`, `StrategyConfig`, `CompactionConfig` (summarizer model, token budget, keep-window, `chunk_turns` for the map-reduce fallback's chunk size, prompt), `LoggingConfig` (minimum `level`, plus output `format` — text/json — and destination settings `console`, `file`, `file_max_bytes`, `file_backup_count`), `AppConfig` (includes `base_prompt`, merged into every agent's leading system message, `compaction`, and `max_sessions`, capping how many distinct `(agent, session_id)` sessions `InMemorySessionStore`, `CostTracker`, and `ContextFootprintTracker` each keep at once before evicting the least-recently-touched one — `None` means unbounded): the startup config models, loaded once from JSON
