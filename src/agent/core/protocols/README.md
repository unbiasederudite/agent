# protocols

Interfaces for anything with interchangeable implementations.

## Contents

- `illm.py` — `ILLM`, implemented by any outbound adapter that can turn messages into a completion (currently: `LiteLLMAdapter`). `complete()` takes optional `temperature`/`top_p`/`max_tokens`; `None` means "use the implementation's own configured default." `max_input_tokens()` returns the model's real context-window size, a local lookup with no network call. Contractual requirement on every implementation: a request declaring no `tools` must never carry `role="tool"` messages or `tool_calls`-bearing messages (Bedrock's Converse API rejects such a request outright), so an implementation folds any such content out of `messages` itself — e.g. via `flatten_tool_exchanges_for_no_tools_request` in `core/models/message.py`, which is what `LiteLLMAdapter` does. Callers may therefore always pass real, un-pre-processed history, whether or not a given call declares tools.
- `itool.py` — `ITool`, implemented by any concrete tool in `core/tools/` (currently: `GetCurrentTimeTool`). `parameters_model: type[BaseModel]` is the schema of record for a tool's arguments -- the LLM-facing JSON Schema is derived from it (`model_json_schema()`), and an LLM's returned arguments are validated against it (`model_validate()`) before `execute()` runs -- a schema mismatch becomes a clean `role="tool"` error message instead of a raw Python exception or a silently-ignored argument. `execute()` is called by whichever `IStrategy` implementation the request routes through.
- `istrategy.py` — `IStrategy`, implemented by any reasoning-loop algorithm in `core/strategies/` (currently: `ReactStrategy`). Owns how (and whether) tools get offered to and invoked by the LLM; receives tools pre-resolved to instances (`dict[str, ITool]`) — name resolution against `ToolRegistry` is the caller's (`AgentRunService`'s) job, so a strategy never sees a tool it wasn't explicitly given. Returns a `Turn`, not a `Completion` — the aggregate of everything the run generated, not one wire call's result. `run()` also takes an optional `max_tool_result_chars`, capping how much of a tool's result content is fed back into the message list -- a longer result is truncated with a trailing marker noting what was cut; `None` means uncapped. Alongside it, `max_tool_calls_per_round` caps how many of one LLM response's tool calls actually execute (the excess are skipped, each replaced with a short error result saying so) and `max_tool_results_total_chars` caps the combined tool-result content across the whole run, replacing every result past that budget with a short omission marker; `None` means uncapped for both.
- `isession_store.py` — `ISessionStore`, implemented by any per-conversation history store in `core/session_stores/` (currently: `InMemorySessionStore`). Async even though the current implementation does no I/O, since a durable backend is the reason this is a protocol at all. `replace()` overwrites a session's stored history entirely -- used by `CompactionService` to swap in a summarized version. `lock()` serializes operations against the same `(agent, session_id)` across concurrent requests, guarding any read-modify-write sequence spanning more than one store call (e.g. `CompactionService.compact()`'s get-summarize-replace) against a concurrent `append()` landing in between and being silently lost; correctness is backend-specific, so each implementation provides whatever locking is actually correct for its own backend. `busy()` gained alongside `lock()`: a non-blocking whole-operation rejection, distinct from `lock()`'s brief store-mutation critical section -- raises `SessionBusyError` immediately if another operation already holds `(agent, session_id)`, rather than waiting, so a second concurrent request against the same session is refused outright instead of silently running against stale context. `delete()` permanently removes an `(agent, session_id)` pair and its stored history.
